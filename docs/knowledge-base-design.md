# 八股知识库设计

## 目标与当前基础

用本地 Markdown 文件构成可持久化、可增量维护、可供人阅读的知识库。文件落盘即保存，Git 可提供版本追踪（提交由用户决定）；不依赖某次聊天的上下文。

现有资料包括四个图解专题及九套面试题集，已按章节转换并保留图片；`01`—`04` 模块已有笔记或规划，`agent/drills/` 已有面试实录，`WEAK_POINTS.md` 已有五条记录。保留这些路径及历史，不重复搬运原文，不将资料目录等同于已审核的知识卡。

## 一、目录与职责

## 二、知识单元与检索

一个知识卡覆盖一个适合独立提问的主题，例如 TCP 三次握手或 MVCC。沿用模块路径，在模块内按需要建立 `topics/`，使用稳定 ID，如 `KB-CN-001`、`KB-DB-001`。`KB-` 前缀区别于现有错题编号 `CN-001`，ID 一旦分配不得因重命名而变化。

卡片包含：标题、别名/关键词、模块、来源位置、资料版本、核验状态、简答、原理、追问、易错点及关联错题。来源至少精确到文件和标题；PDF 页码仅在可确认时填写。每张卡的登记项包括 ID、标题、别名、文件路径和核验状态，维护在知识库入口表中。

阅读顺序是“知识库入口 → 模块 → 知识卡 → 原文章节”。卡片未整理时可直接阅读来源目录；既有笔记继续可读，但未标来源的结论需要复核。

检索顺序：卡片表及模块笔记 → 资料目录及对应原文章节 → 全部原文全文搜索。可用 `rg -n -i --glob '*.md' 'MVCC|ReadView|多版本' knowledge-base 03-database 小林codingMarkdown`。不能因卡片表未命中就认定资料中没有该知识点。

## 三、标准答案与冲突处理

1. 用户明确指定的资料或版本优先；否则优先使用来源可追溯且标记“已核验”的知识卡。
2. 没有已核验卡时，读取原文章节作答；已有模块笔记用于辅助定位和补充。详细图解通常用于原理，面试合集通常用于问法，但不能据此自动裁定矛盾。
3. 同题多份资料合并引用，不丢弃版本与适用条件。原文与卡片冲突时明确列出差异，卡片改为“待核验”，暂停把争议点作为扣分依据。
4. 对库内知识，以库内适用版本为出题、讲解和评分基准；库外扩展需明确标注，不能冒充库内结论。用户采用等价表述应认可，不要求逐字背诵。
5. 转换可能丢失公式、表格或文字。必要时回看 PDF；不能确定的内容标为待核验，不用模型记忆静默覆盖。资料中的明显错误也不应被当作事实灌输，应记录争议并核验。

## 四、新文件入库流程

此版采用 Agent 按约定维护文件的方式，未实现后台监听、数据库或自动导入程序。

1. 将新 Markdown 和配套图片放入原文资料目录的独立子目录，保留原件。PDF 转换不是本次设计的实现范围。
2. 阅读目录及正文，确认主题、版本、可用章节、图片和公式质量；前言、广告、求职推广等不纳入题库。
3. 在 `SOURCES.md` 登记来源 ID、路径、版本、所属模块、导入日期、状态和异常。同资料同版本不重复登记；新版本独立登记，旧版本保留。
4. 以标题、别名、概念和版本查重：同主题补充现有卡来源和差异；新主题创建新卡。不能仅按题目字面去重，也不能把版本差异强行合并。
5. 更新知识库卡片表及对应模块 README；知识点很多时分批整理，明确已处理范围、未处理范围和断点。
6. 检查来源定位、相对链接和图片路径；原文修订后，将受影响的卡片标为待核验并重查其评分依据。
7. 原文已登记即可被 Agent 检索；只有真正读过、整理并核验的卡才能标记已核验，不把“登记完成”说成“全量整理完成”。

## 五、面试、错题与薄弱点闭环

出题前检索并阅读依据，确定必答要点及可选扩展；每次只问一题，等待回答后点评。提出两轮有依据的追问，再根据表现决定是否继续。默认优先到期的红色、黄色项，并穿插新题及绿色回抽。

每题反馈包括正确点、遗漏/错误、库内参考答案、来源位置和下一步练习。每次面试落盘到 `agent/drills/`，记录实际回答与追问、来源、评价、状态变化及未答题；未答题不能记错，不编造用户回答或分数。

`WEAK_POINTS.md` 是状态、最近复习日及下次复习日的唯一权威位置；错题详情只保存题目、错误证据、纠偏、来源和复习历史，不再维护另一份当前状态。

- 🔴：核心概念混淆、无法说明主线、追问卡壳。
- 🟡：主线正确，但缺少来源要求的关键机制、边界或推导。
- 🟢：能独立讲清楚，并完成至少两轮相关追问。阅读答案或说“懂了”不算通关。

建议新红项次日复习，黄色项三日后、绿色项七日后回抽；实际日期按会话所在时区计算并写入台账，不代表自动提醒。复习出错可降级，每次变化需关联面试证据。同一薄弱点多次出错追加历史，不重复创建编号。

现有 `CN-001/002/003/101/102` 保持原编号和状态，后续复习时补齐详情及日期。历史台账中范围可能重叠（如 CN-001 与 CN-102），保留原记录，明确子知识点范围再复核；不得仅凭设计工作修改掌握状态。

## 六、实施边界与验收

本次交付设计、导航、资料登记、模板及 Agent 约定。原文可直接阅读与搜索；尚未把全部资料提炼成卡片，也未迁移历史错题、实现网页或向量检索。

后续每批整理的验收：新资料可从登记表定位；每张卡可回到原文章节；Agent 的标准答案引用实际读过的来源；错题可回溯回答证据；新会话能通过文件恢复进度。数据量增长后如需 SQLite/全文索引或向量检索，可由 Markdown 重建索引，Markdown 仍是权威数据，避免维护两份正文。
