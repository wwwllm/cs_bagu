# 计算机网络第 1 章：计算机网络和因特网（核心架构与底层深度）

## 1. 核心架构与交换机制

### 1.1 电路交换 (Circuit Switching) vs 分组交换 (Packet Switching)
- **电路交换**：
  - 通过频分复用（FDM）或时分复用（TDM）为通信双方预留独占的端到端物理资源。
  - **核心缺陷**：静默期（通信闲置期）信道资源无法被其他节点复用，在突发性强的互联网流量下带宽利用率极低。
- **分组交换**：
  - 报文被切分为较短的数据块（分组，Packet），通过**存储转发（Store-and-Forward）**与**按需共享链路**进行传输。
  - **核心优势**：通过**统计多路复用（Statistical Multiplexing）**，允许多个会话动态按需共享信道，大幅提高链路利用率，能容纳远超电路交换理论上限的并发用户数。

### 1.2 分组首部 (Header) 的本质作用
- 分组交换取消了固定的物理时隙和频段，路由器面对裸比特流无法隐式获知其去向。
- 首部是分组在无连接网络中独立路由的“身份证与物流面单”，路由器据此提取目的 IP，查阅转发表做出自主路由决策。
- *注：乱序到达是分组自主选路与排队时延波动的副作用，而非设计分组加首部的初衷。*

## 2. 网络性能度量与排队论数学推导

### 2.1 四种节点时延
节点总时延定义：
$$d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}}$$

1. **节点处理时延 ($d_{\text{proc}}$)**：检查分组首部、查转发表选路、差错检验，微秒级。
2. **排队时延 ($d_{\text{queue}}$)**：分组在路由器输出缓冲区等待被推入链路的时间。
3. **传输时延 ($d_{\text{trans}}$)**：
   $$d_{\text{trans}} = \frac{L}{R}$$
   将该分组的所有比特推向链路的时间。$L$ 为分组长度（bits），$R$ 为传输速率/带宽（bps）。
4. **传播时延 ($d_{\text{prop}}$)**：
   $$d_{\text{prop}} = \frac{d}{s}$$
   一个比特在物理介质中传播的时间。$d$ 为两节点间物理距离，$s$ 为介质中光电速度（约 $2 \times 10^8 \text{ m/s}$）。

> **高频陷阱区分**：
> - 升级带宽（如 100M $\to$ 1000M）显著降低的是**传输时延**，对传播时延无影响。
> - 在缓冲区排队等待前方分组发送完，属于**排队时延**，不是传输时延。

### 2.2 时延带宽积 (Bandwidth-Delay Product, BDP)
$$\text{BDP} = R \times d_{\text{prop}}$$
表示链路上能够容纳的正在“飞行”的最大比特总数（链路管道的体积），决定了 TCP 发送窗口的最大饱和设计值。

### 2.3 流量强度与排队时延趋于无穷的推导（M/M/1 队列模型）
设到达过程为泊松过程（参数 $\lambda$），服务时间服从指数分布（均值 $L/R$，参数 $\mu = R/L$），流量强度定义为：
$$I = \rho = \frac{\lambda}{\mu} = \frac{La}{R} < 1$$

由生灭过程平衡方程 $\lambda P_k = \mu P_{k+1}$ 递推可得稳态概率分布：
$$P_k = (1 - \rho)\rho^k$$

队列中等待的分组数期望 $N_q$（不包含正在被服务的那个）：
$$N_q = \sum_{k=1}^{\infty} (k - 1)P_k = \frac{\rho^2}{1 - \rho}$$

根据**利特尔法则 (Little's Law)** $N_q = \lambda \cdot d_{\text{queue}}$，代入解得：
$$d_{\text{queue}} = \frac{N_q}{\lambda} = \frac{\rho}{\mu (1 - \rho)} = \frac{L}{R} \cdot \frac{I}{1 - I}$$

**结论分析**：
当流量强度 $I \to 1^-$ 时，分母 $1 - I \to 0^+$，排队时延呈现非线性爆炸，即 $d_{\text{queue}} \to +\infty$。数学与物理根源在于：到达的随机波动性使得“突发极易积压成排队队伍，但空闲时隙无法倒流弥补过去的排队”。

## 3. 队列调度机制与工业级丢包策略

### 3.1 普通排队（FIFO + Drop-Tail）的缺陷
- **无差别丢包**：高突发大流量塞满队列，导致低频但关键的小分组（如 DNS 请求、TCP SYN/ACK 握手包）被动溢出被弃。
- **TCP 全局同步 (Global Synchronization)**：尾部丢弃导致同一链路上的多条 TCP 连接同时发生丢包、同时进入慢启动/拥塞避免减速，造成链路吞吐量出现剧烈的过山车式震荡。

### 3.2 进阶队列调度机制
- **优先级排队 (Priority Queuing, PQ)**：高优队列未空之前绝不调度低优队列，实现关键业务极低时延。
- **加权公平排队 (Weighted Fair Queuing, WFQ)**：按业务流划分权重按比例轮转调度，隔绝单流恶意抢占。
- **主动队列管理 (WRED)**：在队列达到拥塞上限之前，依据设定的阈值曲线按概率提前随机丢弃低优报文，平滑触发 TCP 错峰拥塞减速。

### 3.3 高优先级队列已满、低优未满时的丢包判定
- **判定结果**：高优先级报文**依然会被丢弃**。
- **底层原因**：
  1. **防饿死与雪崩**：防止配置失误或伪造高优的恶意洪流（DDoS）吞噬全局缓冲区，导致系统死锁和低优流量彻底饿死。
  2. **硬件内存分配**：采用静态配额（Static Partitioning）时各队列隔离；采用动态共享池（Dynamic Thresholding）时，高优借用共享内存受硬性动态上限系数 $\alpha$ 约束，越界即丢。
  3. **流量监管 (Policing)**：在入队之前通常配有**令牌桶 (Token Bucket)**，违规超额高优流量被强制降级或丢弃。
